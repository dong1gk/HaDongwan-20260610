# 영양제핏

> 35~50세 여성을 위한 건강기능식품 AI 구매 판단 도우미

내 건강 고민과 현재 복용 루틴을 바탕으로, 나에게 맞는 영양제를 3개로 압축해주는 AI 구매 도우미입니다.

---

## 1. 문제 정의

35~50세 여성은 이미 온라인에서 건강기능식품을 활발하게 구매하고 있지만, **"어떤 제품이 나에게 맞는지"를 판단하는 일**은 여전히 어렵습니다. 제품이 없어서가 아니라, 제품·리뷰·광고 문구가 너무 많고 **개인화된 구매 판단**이 없기 때문입니다.

| 기존 채널 | 강점 | 공백 |
|---|---|---|
| 쿠팡 | 빠른 구매, 배송, 가격, 리뷰 | 건강 고민 → 성분/제품군 변환, 복용 루틴과의 중복 확인, 개인화된 성분·함량 설명 |
| 네이버 쇼핑 | 가격 비교, 검색, 블로그 정보 | 정보는 많지만 결정 피로를 줄여주지 못함 |
| 필리·핏타민 등 맞춤 영양제 서비스 | 개인화 | 긴 설문 온보딩, 구독 부담, 영양제만을 위한 별도 플랫폼이라는 진입 장벽 |

**영양제핏은 무거운 맞춤 영양제 구독 서비스가 아니라, 커머스 경험 안에 들어가는 가벼운 "구매 판단 레이어"입니다.**

⚕️ 영양제핏은 **진단이 아니라 구매 판단 보조**입니다. 건강 상태가 걱정되거나 약을 복용 중이라면 전문가와 상담하세요.

## 2. 타깃 고객

온라인에서 영양제를 구매하거나 구매를 고민 중이지만, 제품 선택에 어려움을 겪는 **35~50세 여성**.

## 3. 핵심 MVP 플로우

```
자연어 대화로 건강 고민 입력 → AI가 부족한 정보만 추가 질문(연령/복용 루틴/예산/우선순위)
→ 성분/제품군 변환 → 후보 압축(규칙 기반 스코어링) → Top 3 추천(AI 설명)
→ 성분·함량 비교 → 크롤링 기반 신뢰 정보 → 최종 구매 확인 카드
```

## 4. 구현된 기능

1. **랜딩** — 서비스 가치 제안 + 의료 진단이 아니라는 고지
2. **대화형 AI 인테이크** — 설문 대신 채팅으로 시작. "요즘 너무 피곤하고 잠도 못 자요"처럼 자연어로 말하면 AI가 이미 파악한 정보는 다시 묻지 않고, 부족한 정보(연령대/복용 루틴/예산/우선순위)만 한 번에 하나씩 추가 질문. 빠른 답변을 위한 퀵 리플라이 버튼 제공. AI 사용 불가 시 5문항 설문으로 자동 폴백
3. **고민 → 성분군 변환** — 예: 피로 → 비타민B, 마그네슘, 코엔자임Q10
4. **복용 루틴 중복 체크** — 자유 입력 텍스트를 파싱해 `중복 가능성 있음 / 주의 필요 / 비교적 중복 낮음` 판정 (예: 종합비타민 복용 중 → 비타민B 제품 중복 경고)
5. **제품 후보 DB** — 13개 시드 제품 (성분, 함량, 복용법, 가격, 리뷰 수, 주의사항 등 구조화)
6. **크롤러** — axios + cheerio로 공개 위키백과 성분 페이지 수집 (아래 8번 참고)
7. **규칙 기반 후보 압축** — 점수화하여 5~7개 후보로 압축
8. **OpenAI 추천 설명** — 후보와 크롤링 자료를 프롬프트에 넣어 한국어 추천 사유 생성
9. **Top 3 추천 UI** — 순위, 적합도, 배지(고민 적합/중복 낮음/가성비 좋음 등), 추천 이유, 주의점
10. **성분·함량 비교 테이블** — 제품명/핵심 성분/함량/1일 섭취량/복용 편의성/주의사항/1일 비용/추천 이유
11. **신뢰 근거 섹션** — 리뷰 요약, 반복 장점/단점, 광고성 후기 주의, **크롤링 기반 참고 정보**
12. **비용 계산** — 총 가격/개수/예상 일수/하루 비용/월 비용 (예: 하루 기준 약 138원, 월 기준 약 4,140원)
13. **구매 전 최종 확인 카드** — 추천 이유 / 확인할 점 / 가격 판단 / 최종 판단
14. **실구매 연결** — Top 3 카드마다 구매 페이지로 이동하는 버튼 제공. 기본은 네이버쇼핑 성분 검색 링크이며, `server/data/products.json`의 `productUrl`에 올웨이즈 상품 공유 링크를 입력하면 해당 제품은 "올웨이즈에서 보기" 버튼으로 자동 전환됨.
    - *올웨이즈 링크를 기본으로 쓰지 않은 이유*: 올웨이즈는 앱 중심 플랫폼으로, 웹에는 검색 페이지가 없고 개별 상품 딥링크(`/items/:itemId`)만 존재합니다. 성분 단위로 동적으로 연결할 수 있는 공개 검색 URL이 없어, 데모의 안정성을 위해 검색 URL을 제공하는 네이버쇼핑을 기본으로 사용하고 올웨이즈는 상품별 공유 링크 방식으로 지원합니다.

## 5. 기술 스택

- **Frontend**: React 18 (JavaScript) + Vite, 순수 CSS
- **Backend**: Node.js + Express (JavaScript)
- **AI**: OpenAI API (공식 `openai` JavaScript SDK)
- **Crawling**: axios + cheerio
- **State**: React `useState` (Redux 불필요)

## 7. OpenAI API 사용 방식

- API 키는 **백엔드 환경변수(`OPENAI_API_KEY`)에만** 저장되며 프론트엔드에 절대 노출되지 않습니다.
- 흐름: 프론트엔드 → 백엔드 `POST /api/recommend` → 백엔드가 OpenAI 호출 → 한국어 구조화 JSON 응답 반환
- 모델은 `OPENAI_MODEL` 환경변수로 변경 가능 (기본값: `gpt-4o-mini`)
- AI는 두 곳에서 사용됩니다: ① **대화형 인테이크**(`POST /api/chat`) — 자연어에서 고민/연령/루틴/예산/우선순위를 추출하고 부족한 것만 질문, ② **추천 설명 생성**(`POST /api/recommend`) — 압축된 후보와 크롤링 자료를 바탕으로 한국어 추천 사유 작성.
- 시스템 프롬프트에서 의료 진단 금지, 치료/완치 표현 금지, 후보 목록 내에서만 선택, 한국어 출력을 강제합니다.
- AI 호출 실패(키 미설정, 쿼터 초과 등) 시에도 데모가 끊기지 않습니다: 인테이크는 5문항 설문으로 폴백하고, 추천은 **규칙 기반 폴백**으로 동일한 형태의 결과를 생성합니다. (화면에 폴백 안내 배너 표시)

### API 엔드포인트

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/health` | 서버 상태 |
| GET | `/api/products` | 시드 제품 DB |
| GET | `/api/crawl/sample` | 캐시된 크롤링 데이터 (`?refresh=true`로 라이브 크롤링) |
| POST | `/api/crawl` | 라이브 크롤링 실행 + 캐시 갱신 |
| POST | `/api/chat` | 대화형 인테이크 — 대화 기록을 받아 다음 질문 또는 완성된 프로필 반환 |
| POST | `/api/recommend` | 사용자 프로필 → 규칙 기반 압축 + AI 추천 JSON |

## 8. 로컬 실행 방법

```bash
# 1) 백엔드
cd server
npm install
cp .env.example .env   # OPENAI_API_KEY 입력
npm run dev            # http://localhost:5001

# 2) 프론트엔드 (새 터미널)
cd client
npm install
npm run dev            # http://localhost:5173
```

로컬 개발에서는 Vite 프록시가 `/api` 요청을 `localhost:5001`로 전달하므로 클라이언트 `.env`는 비워둬도 됩니다.

```bash
# (선택) 크롤링 캐시 갱신
cd server
npm run crawl
```

### 테스트 시나리오

서버·클라이언트 실행 후 http://localhost:5173 접속 (배포 링크도 동일한 흐름):

1. **대화형 추천 (기본 흐름)** — "시작하기" 클릭 후 채팅에 자연어로 입력
   - 예시: `요즘 너무 피곤하고 잠도 잘 못 자요`
   - AI가 이미 파악한 정보는 다시 묻지 않고, 부족한 것(연령대/복용 영양제/예산/우선순위)만 추가 질문합니다. 답변은 직접 입력하거나 퀵 리플라이 버튼을 탭하면 됩니다.
   - 한 번에 모두 말해도 됩니다: `눈이 침침해요. 45살이고 오메가3 먹는 중이에요. 예산은 4만원대, 성분 함량이 중요해요`
2. **복용 루틴 중복 체크** — 복용 중인 영양제에 `종합비타민`을 포함해 입력하면, 결과 페이지에서 비타민B 계열 중복 경고와 "성분 함량 확인 필요" 배지를 확인할 수 있습니다.
3. **크롤링 데이터 활용 확인** — 결과 페이지 "믿을 수 있는 근거 확인" 섹션의 **크롤링 기반 참고 정보** 박스에서 위키백과 성분 문서 요약·출처 링크·수집 시점을 확인할 수 있습니다.
4. **AI 폴백 동작 (선택)** — `server/.env`에서 `OPENAI_API_KEY`를 비우고 재시작하면, 채팅은 5문항 설문으로 폴백되고 추천은 규칙 기반 결과 + 안내 배너로 표시됩니다.
5. **API 단독 테스트 (선택)**
   ```bash
   curl http://localhost:5001/api/health
   curl http://localhost:5001/api/products
   curl "http://localhost:5001/api/crawl/sample?refresh=true"   # 라이브 크롤링 실행
   ```

> 배포 링크 첫 접속 시 무료 서버(Render)가 깨어나는 데 30~50초가 걸릴 수 있습니다. 랜딩 페이지 진입 시 자동으로 서버를 깨우므로, 잠시 후 채팅을 시작하면 정상 속도로 동작합니다.

## 11. 설계 의도

- **설문 대신 대화로 시작하는 이유** — 맞춤 영양제 서비스의 가장 큰 진입 장벽이 긴 설문 온보딩입니다. 영양제핏은 고객이 점원에게 말하듯 자연어로 고민을 이야기하면, AI가 이미 파악한 정보는 건너뛰고 부족한 것만 묻습니다. 같은 정보를 모으더라도 "설문을 작성하는 경험"이 아니라 "상담받는 경험"이 되도록 설계했습니다.
- **의료 진단이 아니라 구매 확신에 집중하는 이유** — 고객의 실제 문제는 "내 몸의 진단"이 아니라 "장바구니 앞에서의 망설임"입니다. 법적·윤리적 리스크를 피하면서 커머스 맥락의 가치를 만듭니다.
- **규칙 기반 필터링 + AI 설명을 결합한 이유** — AI가 전체 카탈로그에서 자유롭게 고르면 환각과 일관성 문제가 생깁니다. 백엔드가 예산·중복·고민 적합성으로 후보를 먼저 압축하고, AI는 그 안에서 순위와 설명만 담당해 신뢰성과 비용 효율을 확보합니다.
- **크롤링 데이터를 신뢰 근거로 쓰는 이유** — "이 추천이 어디서 왔는가"에 답하기 위해, 판매 페이지가 아닌 공개 성분 문서를 출처 링크와 함께 보여줘 광고성 정보와 분리된 참고 자료를 제공합니다.

## 12. 한계와 향후 개선
